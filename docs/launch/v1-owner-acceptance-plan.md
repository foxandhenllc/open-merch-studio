# V1 owner acceptance preparation

Active goal, September 12, 2026: make the supported single-merchant V1 experience ready for Chris to
exercise as a creator/community-brand owner. Readiness for owner testing precedes release approval,
physical-sample evidence, and a V1 tag.

## Implementation sequence

1. Find and review older orders; apply the exception filter across the full installation history.
2. Customize logo, share image, and domain settings through reviewed owner controls.
3. Guide and resume the supported installation/account-connection path with actionable checks.
4. Enforce collection-specific personalization and bind submitted artwork to the owner's product,
   layout, and price; keep fixed artwork unchanged.
5. Rehearse database/private-file backup and restore, preserving owner configuration and orders.
6. Provide a repeatable owner-testing environment and an acceptance walkthrough, with clear local
   simulation labels and safe samples for the approved personas.
7. Run the final source, database, browser, installation, and dependency checks; commit the tested
   source and hand off the exact starting command/URL and remaining live-only validation.

## Acceptance outcomes

- Start a fresh installation without inheriting another merchant's identity or private data.
- Understand what is simulated and what requires an owned provider account.
- Configure brand/contact/policies/assets and see the reviewed result consistently.
- Create, review, publish, buy, update and withdraw a collection through the supported workflow.
- Choose supported customer artwork behavior; server checks preserve its constraints.
- Find orders, inspect exact saved prints, record review and recover an eligible failure.
- Resume unfinished setup and recover an isolated backup without losing configuration/artwork.
- Complete each task on a phone and desktop without editing application source.

## UI approach

Keep admin a calm workspace with a clear next action and specific recovery guidance. Brand assets
and collection artwork provide the visual identity; configuration controls stay compact. Preserve
selection while navigating and make saved, reviewed, deployed, and simulated states distinct.

Scenario-specific Twitch ingestion, competitions, voting, subscriptions and arbitrary workflow APIs
remain later client-style forks. Test the reusable foundation with rights-cleared supplied artwork,
AI fixtures, and explicit reviewed orders rather than claiming those integrations already exist.
